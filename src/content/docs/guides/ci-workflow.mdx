## Partes involucradas

```
ERP.Core.Manager.Api (backend)                erp-api-docs (este repo)
┌────────────────────────────────┐            ┌──────────────────────────────┐
│ Docs/                          │            │ 1. Descarga Docs/**/*.md     │
│   <Módulo>/<Endpoint>Docs.md   │  release   │ 2. Solo los .md existentes   │
└────────────────────────────────┘  repo_    │ 3. Sync -> src/content/docs  │
              ▲          dispatch ─────────▶ │ 4. Build (Astro Starlight)   │
              │                   ─────────▶│ 5. Si no hay .md => aborta    │
              │ (solo .md presentes)         │ 6. GitHub Pages               │
              │                              └──────────────────────────────┘
```

## 1. Backend: publicar la release

Al publicar una release en `ERP.Core.Manager.Api`, se dispara este repo con un
`repository_dispatch` (evento `api-released`). Es opcional: el sitio puede regenerarse
con `workflow_dispatch` manual.

## 2. Este repo: descargar `Docs` desde el backend

El workflow `.github/workflows/publish.yml`:

1. Descarga el directorio `Docs` del backend vía la **GitHub Contents API**
   (`scripts/fetch-backend-docs.mjs`), copiando **solo los `.md`**.
2. Si **no encuentra ningún `.md`**, termina con error y **no despliega nada**.
3. `scripts/sync-docs.mjs` inyecta el `title`/`module` y copia los archivos a `src/content/docs/api/`.
4. `astro build` genera el sitio.
5. Se publica en **GitHub Pages** (`dist/`).

## Configuración requerida (repo variables/secrets)

| Nombre | Tipo | Uso |
|---|---|---|
| `BACKEND_REPO` | Variable | Repo del backend, p. ej. `alpac-organization/ERP.Core.Manager.Api` |
| `BACKEND_DOCS_PATH` | Variable | Ruta del directorio `Docs`, p. ej. `src/ERP.Core.Manager.Api/Docs` |
| `BACKEND_REF` | Variable | Rama/tag a leer, p. ej. `develop` |
| `BACKEND_READ_TOKEN` | Secret | Token con acceso de lectura al repo del backend (si es privado) |

## Ejecutar en local

```bash
# 1. Clonar/copiar el directorio Docs del backend local (o usar la ruta del repo)
node scripts/sync-docs.mjs --source="..\Back-End\ERP.Core.Manager.Api\src\ERP.Core.Manager.Api\Docs"

# 2. Levantar el sitio
npm run dev
```

Los archivos bajo `src/content/docs/api/**` son generados: se sobrescriben en cada sincronización.
